# Feature parity matrix

Updated: 2026-07-10

This document is the authoritative migration ledger for retained behavior. It must be updated with every implementation milestone. Legacy tests are supporting evidence only; active legacy code is authoritative when the two disagree. For ESP-observable behavior, `.old/slaveCode/ESP32Code/ESP32Code.ino` is primary.

Status values:

- **Not started**: no working replacement exists.
- **Partial**: some foundation or behavior exists, but the retained workflow is not usable end to end.
- **Implemented**: implementation and the listed unit/integration/browser evidence exist and pass.
- **Blocked**: implementation cannot meet the contract without an explicit decision or new authority.

## Known legacy discrepancies and migration hazards

1. The legacy interleaved batching test expects three batches, while the executed manager resets all per-device counts after a flush and produces two. The running code wins; the foundation test reflects two.
2. `clear` is a bare broadcast with plaintext replies. The manager's targeted expectation is incompatible with firmware.
3. `syncTime` in a schedule is stored but does not set the firmware clock; only `sync` does.
4. `currentSchedule` is a 4096-byte C buffer, so a terminating NUL makes 4095 bytes the conservative maximum safe serialized schedule.
5. Host PWM values are 0-255 even when device resolution exceeds eight bits; firmware schedule evaluation scales to resolution.
6. Ordered case-sensitive prefix matching, an empty mapping key, case-distinct channel names, hidden `mainLys70` gain, and missing throttles must be reported by import without silent repair.
7. Firmware versions `0`, `1`, and `2w` do not receive schedules in the current host.

## Explicit exclusions

The following are not parity evidence and remain deferred unless separately authorized:

- `.old/sketch5.html` dashboard, switches, sensors, countdowns and simulated DSL flows.
- DSL dosing and pump calibration workflows described only in `old_todo.txt`.
- Direct Pi sensors and dormant USB Arduino support.
- Legacy login template, remote access, HTTPS certificate management and public exposure.
- Kill, shutdown, reboot, git-pull and self-update routes.

The active UI parity sources are `/`, `/control/<device_type>`, and `/logs` only. Unsafe Python `eval`, global response queues, raw JSON writes, hardcoded infrastructure and silent error handling are implementation defects, not retained behavior.
